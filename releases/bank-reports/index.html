Bank reports agent, answers from annual reports with the page they come from.

Questions across French banks' annual reports, answered with page-level citations. A plain RAG pipeline against an agent that checks its own figures.

github.com/hajar6883/bank-reports-agent

Premise

A bank's universal registration document runs to several hundred pages, and the figures that matter (capital ratios, net income, cost of risk) sit mostly in tables. Extract those tables as plain text and the rows and columns collapse into a stream of numbers: the model can no longer tell which figure belongs to which year.

Comparisons make it worse. "Compare the CET1 ratios of BNP Paribas and Société Générale" needs one fact from each report; a single retrieval pass often returns both passages from the same bank.

The question: how much accuracy does an agent buy on multi-bank and table questions, and at what cost in tokens and latency?

What it does

01  ingest    page-aware chunks; tables kept as markdown, stored separately
02  search    dense (pgvector) + full-text in one Postgres, merged with RRF
03  serve     search exposed as an MCP server: list, search, read a page
04  agent     plan per bank → retrieve → answer → check figures, retry if unsupported

Every chunk stays on one page, so every citation points at one page. The agent is a fixed graph with a capped number of retries rather than an open loop: the worst-case cost is known in advance, and each step can be inspected.

Design choices

  • Hybrid search. Meaning-based search finds "solvency" for "CET1"; keyword search finds "CET1" and "31 December 2025" exactly. Reciprocal Rank Fusion merges them on ranks alone, so their scores never need calibrating.
  • One database. Vectors, full text and filters all live in Postgres, with no second system to run.
  • MCP for tools. The agent reaches search over the protocol, not by import, so the same tools work unchanged in Claude Desktop or any other MCP client.
  • A verifier, measured. A third mode runs the agent without its check step, to isolate what the verifier adds.

Evaluation

Three modes (baseline RAG, agent without check, full agent) on a hand-labelled set of 40 questions: single bank, multi-bank and table.

Context recallDid retrieval find the right page?

Tokens, latency, costWhat the accuracy costs, per question.

Results will be published here once the gold set is fully labelled. A retrieval-only ablation (dense vs keyword vs hybrid) runs without any LLM calls.

Get it

Python, Postgres with pgvector, FastAPI. A fake model runs the whole pipeline without an API key, to check the plumbing. Setup and commands are in the README on GitHub.
